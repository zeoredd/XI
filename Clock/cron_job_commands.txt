Timers to add (recommended schedule)

Daily (03:00)

Protocol Sentinel + AI task (edge cases):
runtime.routines_orchestrator --sentinel --sentinel-ai-edgecases 

Daily (03:10)

Consume AI task (ask sentinel agent, apply overlays, re-index):
runtime.routines_orchestrator --sentinel-ai-consume 

Daily (03:20)

Rollups (weekly/period/quarterly if due), amendments sweep, indexer one-shot + ensure daemon:
runtime.routines_orchestrator --run-all
(this runs rollups → sweep → index → sentinel quick if you enable it; you can also call sub-flags explicitly) 

Daily (04:00)

Quick Sentinel window (sanity on last few hours):
runtime.routines_orchestrator --sentinel-quick --sentinel-window-hours 2 

Daily (04:30)

Sandbox cleanup (temp artifacts): already in the orchestrator as sweep_sandbox(); put it on a timer if you want it independent:
python tools/sandbox_retention.py --root ./sandbox --days 21 

Weekly (Sun 04:45)

DB hygiene (Postgres): VACUUM (ANALYZE) tables used by memory/indexer; optionally REINDEX if you see bloat.

Weekly (Sun 05:15)

Log rotation + old archives prune (keep N months).

Monthly (1st 05:30)

Full consistency sweep: re-run indexer --all (cold read) for drift detection.

Model/embedding fingerprint check (alert if embedder changed vs. DB fingerprint).

Backup memory/ and DB dump (logical pg_dump).

Why these timers

You already have the orchestrator hooks for rollups, indexer one-shot, ensuring daemon, and Sentinel audits—including quick mode and the AI edge-case mode we added. Scheduling them at night staggers load and keeps daytime flows snappy.

-----------------------------
